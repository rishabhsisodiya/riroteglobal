Enterprise ERP / Infrastructure

Unified ERP & Service Platform

📍 India · Infrastructure Services Group

Solo Delivery

Unified ERP platform merging an ACE after-sales service ticketing system with 11 role-based executive dashboards — one PostgreSQL database, one auth/role system, one Next.js frontend, replacing two separate codebases and servers. Solo full-stack delivery for 9 business entities across 5 ERPNext v15 Frappe Cloud sites.

  • Ticketing engine on NestJS + Prisma: 8 creation sources → a single CreateTicketService → 9-state workflow, with a responsive/PWA Field Service Visit flow and 15 email + SMS notification triggers
  • Two-way ERPNext integration: read-only nightly MariaDB master pull + REST-API-only writes (Stock Entry, draft Sales Invoice) and an inbound webhook — no direct DB writes, Frappe permission engine respected
  • 11 role-specific dashboards (Sales Head, Finance Head, MD, Manufacturing Head & more) on Next.js 14 App Router + React 19
  • Node.js middleware: ERPNext role sync, Promise.all multi-site fan-out across up to 5 sites, Redis per-widget caching — sub-500ms loads vs 5s+ sequential; mock/live toggle via single env flag
  • Sales Head dashboard: Decision Band (pace-to-target), pipeline funnel with bottleneck detection, deal drawer with activity timeline

Enterprise ERP / Manufacturing

Foundry Operations ERP

📍 India · Manufacturing

Full Stack

A domain-specific foundry ERP that owns all foundry-operational data end to end — sales-order-to-dispatch, production planning, melting & metallurgy, quality, inventory, maintenance and costing — across a 17-module map, with heat-number genealogy as the golden traceability key. Integrates with the client's existing ERPNext only for finance and payroll.

  • Translated a 100+ doctype functional/solution spec into a NestJS + Prisma + PostgreSQL backend and a Next.js 16 / React 19 App Router frontend
  • Delivered the RBAC foundation (admin-configurable roles, segregation-of-duties rules), audit logging, and 12+ master-data modules with full CRUD
  • Short-lived JWT access tokens backed by rotating, hash-only-stored refresh tokens (rotation-on-use replay protection) with a de-duped silent-refresh interceptor
  • ERPNext integration boundary — REST/JSON only, no DB-to-DB — with idempotent correlation-ID calls, retry/backoff queues, and a nightly reconciliation run for one-sided records
Next.js 16 React 19 TypeScript NestJS Prisma PostgreSQL SWR Tailwind CSS JWT ERPNext
